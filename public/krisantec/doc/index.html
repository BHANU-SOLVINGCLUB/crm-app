Section 1 · Overview

Krisantec CRM

A modular, industry-aware CRM platform that adapts every page — fields, campaigns, platforms, funnels, sample data — to the active business vertical. Built as a frontend-first preview with persisted local state and zero backend.

Vision

One CRM ecosystem covering marketing, sales, finance, operations, support and retention across healthcare, real estate, e-commerce, SaaS, education, manufacturing, hospitality and agency businesses. Switch the industry from the top bar — and the entire workspace re-shapes itself.

Marketing engine

The Marketing module surfaces five distinct content blocks, each industry-aware:

  • KPI strip — spend, leads, conversions, avg cost-per-lead with month-over-month deltas.
  • Performance trend — 7-day area chart of leads & conversions.
  • Conversion funnel — stages relabeled per industry (e.g. Inquiries → Quotations → Orders for manufacturing vs Trial Signups → Activated → Paid for SaaS).
  • Platforms in play — vertical-relevant platforms (Practo / 99acres / IndiaMART / LinkedIn / etc.) with spend, CPL, CTR, leads, conversions.
  • Creatives library — gallery of ad creatives with status (Live / Paused / Draft / Review), type, impressions, clicks, CTR.
  • Active campaigns — table with budget burn-bar, channel, objective, reach, leads, conversions, dates.

Section 3 · Tech Stack

How it's built

A small, fast, modern frontend stack. No backend, no database. State is stored in the browser via localStorage with Zustand's persist middleware.

Frontend stack

React v19
UI library. Functional components only, no class components.
TypeScript v6
Strict types across data models, store and components.
Vite v8
Dev server, HMR, production bundling. Custom middleware for the doc route.
Tailwind CSS v3
Utility classes + custom theme tokens (panel, line, brand-blue, etc.).
Zustand v5
Tiny global store with built-in persist for industry + lead overrides.
React Router v7
Client-side routing for Dashboard / Marketing / Leads.
Recharts v3
Area, line and bar charts for trend, funnel and platform analytics.
Lucide React latest
Icon set used across sidebar, topbar, modules and stat cards.

Section 4 · API Reference

API & data layer

There's no HTTP backend yet — the “API” is the typed data layer + the Zustand store. All data shapes below come straight from src/data/*.ts.

Core data models

typeIndustryKey

type IndustryKey =
  | 'healthcare'
  | 'realestate'
  | 'ecommerce'
  | 'saas'
  | 'education'
  | 'manufacturing'
  | 'hospitality'
  | 'agency'

interfaceIndustry

interface Industry {
  key:     IndustryKey
  name:    string
  tagline: string
  icon:    LucideIcon
  accent:  string     // hex color (e.g. '#10b981')
  emoji:   string
}

interfaceMarketingData

interface MarketingData {
  stats:     MarketingStats      // totals + deltas + trend + funnel
  platforms: PlatformStat[]      // 5–6 channels with spend/leads/conv/CPL/CTR
  creatives: Creative[]          // gallery items with status & perf
  campaigns: Campaign[]          // goal-driven multi-channel campaigns
}

interface PlatformStat {
  name: string;       spend: number;       leads: number
  conversions: number;  cpl: number;         ctr: number
  color: string;      icon: string
}

interface Campaign {
  id: string;        name: string;        channel: string
  objective: 'Awareness' | 'Lead Gen' | 'Conversion' | 'Retention' | 'Engagement'
  status: 'Running' | 'Scheduled' | 'Paused' | 'Completed'
  budget: number;     spent: number;     reach: number
  leads: number;      conversions: number
  startDate: string;  endDate: string
}

interfaceLeadSchema & LeadRow

type LeadColumnType =
  | 'text' | 'email' | 'phone' | 'select'
  | 'number' | 'currency' | 'date'

interface LeadColumn {
  key: string;       label: string;     type: LeadColumnType
  options?: string[];  width?: number
}

interface LeadSchema {
  columns:  LeadColumn[]
  sources:  string[]
  statuses: string[]
}

type LeadRow = Record<string, string | number>

Industry store

The single source of truth, defined in src/store/industryStore.ts:

MemberTypeDescription
statecurrent IndustryKey Active industry, persisted to localStorage.
actionsetIndustry(key) (IndustryKey) => void Switch the active industry — every page re-renders with new data.
stateleadsOverrides Partial<Record<IndustryKey, LeadRow[]>> Per-industry user edits to the leads sheet.
gettergetLeads(key) (IndustryKey) => LeadRow[] Returns user overrides if present, otherwise the seeded sample rows.
actionsetLeads(key, rows) (IndustryKey, LeadRow[]) => void Replace rows for an industry. Persisted automatically.
actionresetLeads(key) (IndustryKey) => void Delete overrides for an industry — sample data is restored.
hookuseCurrentIndustry() () => Industry Convenience hook that returns the full Industry object for the active key.

Usage example

import { useIndustryStore, useCurrentIndustry } from '@/store/industryStore'
import { marketingByIndustry } from '@/data/marketing'

function SpendCard() {
  const industry = useCurrentIndustry()
  const key = useIndustryStore(s => s.current)
  const data = marketingByIndustry[key]
  return <div>{industry.name}: ₹{data.stats.totalSpend}</div>
}

Extending the app

Add a new industry

  1. Add the key to the IndustryKey union in src/data/industries.ts.
  2. Push a new Industry entry (name, tagline, icon, accent, emoji) to the industries array.
  3. Add a corresponding MarketingData object to marketingByIndustry in src/data/marketing.ts.
  4. Add a corresponding LeadsConfig to leadsByIndustry in src/data/leads.ts.

Add a new lead column

// src/data/leads.ts → leadsByIndustry.healthcare.schema.columns
{
  key:   'priority',
  label: 'Priority',
  type:  'select',
  options: ['Low', 'Medium', 'High', 'Urgent'],
  width: 110,
}

The sheet picks up the new column automatically. Existing rows return undefined for it until edited.

Add a new platform / creative / campaign

Append entries to marketingByIndustry[<key>].platforms, .creatives, or .campaigns. The Marketing page rerenders automatically.

Wiring a real backend later — replace the static imports in src/data/*.ts with fetch calls inside the store, or introduce a thin API layer (e.g. src/api/marketing.ts) that mirrors the same interfaces. Pages and components stay unchanged because they consume the typed shapes, not the source.
